# 骑士飞行棋 7 项体验修正 · 技术规格

> 项目：`g:\AI\app逆向\KnightChessGodot`（Godot 4.3 / GDScript）
> 目标：按用户 7 条反馈逐条修正，不更换引擎、不另起炉灶，沿用现有 `Main.gd`（流程）、`Hud.gd`（界面）、`Arena.gd`（3D 场景/特效）、`SaveStore.gd`（存档）结构。

## 0. 已确认的现状

- 环道点在 `Main._apply_board_size(n)` 内程序化生成：半径为 `940*grow`，起始角固定 `a0 = -168.7°`。
- 终点跑道 GL 点来自 `assets/data/board.json`，按 `grow*2.04` 缩放，四条跑道分别落在 180°/270°/0°/90° 轴上。
- 每队路径长度 = `n`，路径末格索引 `(team*step + n - 1) % n`，`step = n/4`。
- 相机：`fov 36`、`pitch 48°`、`cam_dist 3700*(1+0.58*(grow-1))`、目标 `(0,40,0)`。
- 存档槽：0 号自动槽 + 1..19 手动槽，`SaveStore` 已有 fmt/分区/extra 扩展位。
- 局域网：UDP 发现 + TCP 定长帧，房主权威，客机发 intent 快照。
- 已有 `Hud.show_item_toast()` 仅在角落短暂播报，未说明施放者/目标。

## 1. 终点跑道对齐（三套主题 / 所有格数）

### 根因
环道起始角 `-168.7°` 与四条跑道所在的 180°/270°/0°/90° 轴相差约 2.3°；且固定角度只在 40 格时接近，52/64 格偏差更大。最后一格（进入跑道的格子）因此与跑道入口错位。

### 决策
把起始角改为随格数计算，使**每队路径末格正好落在对应跑道轴线上**：

```
a0 = 360° / n - 180°
```

推导：路径末格索引 `(t*step + n - 1) % n`，`step = n/4`，其角度 = `a0 + 90t + 360 - 360/n`；代入上式得 `180 + 90t`，与 GL1..GL4 轴完全一致。

### 改动
- `src/Main.gd` → `_apply_board_size(n)`：`var a0 := deg_to_rad(-168.7)` 改为按上式计算的 `a0`；保留半径、格子尺寸、基地方位不变（基地仍与出生格同轴）。
- 不改动 `board.json` 与 `Arena._build_goal_lanes()` 的 GL 缩放逻辑。

### 验收
- 40 / 52 / 64 格各截图一张，四条跑道入口的中心线与对应环道末格中心线重合，无横向错位。
- 六套主题（cozy/dusk/frost/ember/jade/void）至少各核一遍（用户所述“三套主题”，项目现为六套，按全部核）。

## 2. 棋盘整体放大、重算布局比例

### 根因
`cam_dist=3700`、`fov=36` 时，可玩环道只占屏幕约 70% 宽，单格约 35px（1280 宽），文字/棋子偏小；但直接把棋盘拉大会让最外侧基地或近端格出屏。

### 决策
以“可玩区外接半径 R≈1250 世界单位（环道 940 + 基地外沿）”为取景基准，按 16:9 屏幕和相机俯角计算距离，放大到环道占屏约 88–92%，并把镜头目标向相机方向平移，使棋盘整体略上移，避开底部道具栏。

### 改动
- `src/Main.gd` → `_fit_camera()`：
  - `fov` 36 → 34。
  - `pitch` 48° → 50°（更接近俯视，减少远端遮挡，单格更方）。
  - `cam_dist` → `3040.0 * (1.0 + 0.55 * (grow - 1.0))`（40 格时约 3040；52 格约 3517；64 格约 4073）。
  - `cam_target` 由 `(0, 40, 0)` 沿“目标→相机”水平方向偏移约 85 世界单位（让棋盘在屏幕上移约 25–35px）。
  - 在函数内写明取景公式注释：`可见竖向世界高度 = 2*d*tan(fov/2)`，`棋盘投影竖向高度 ≈ 2*R*sin(pitch)`。
- `src/Hud.gd`：右下角道具栏宽度 356 → 320，折叠把手同步；底部提示字号不变。为棋盘让出右下区域。

### 验收
- 1280×720 下截图：环道宽度 ≥ 画面宽度 85%，单格直径 ≥ 40px；最外侧基地、近端与远端环道格均在屏内且不被 HUD 完全遮挡。
- 40/52/64 格均可；六主题各截图确认无出屏。

## 3. 动画放慢 + 吃棋动画重做

### 3.1 全局节奏
- `src/Main.gd`：新增 `const BASE_TIME_SCALE := 0.9`；`_ready()`、`_start_match()`、吃棋慢动作恢复处统一使用它（不再写死 `1.0`）。
- 落子跳跃 `Arena` 的 `hop` 时长：每格 0.08 → 0.10 起跳 / 0.08 → 0.12 落下；骰子滚动时长 +10%。
- 不把全局 `time_scale` 降到 0.8 以下，避免 AI 等待、UI 反馈变拖沓。

### 3.2 吃棋「一跃而起 · 踩成一滩」
重写 `src/Arena.gd` → `capture_stomp(a, b)`，阶段（缩放时间，全局再乘 0.5 慢动作）：

| 阶段 | 时长 | 表现 |
|---|---|---|
| 蓄力 | 0.22s | 攻击方下蹲（y 轴压扁 0.8）、身体前倾，目标方轻微发抖 |
| 跃起 | 0.42s | 抛物线跃到目标正上方，身体拉长（1.2 高），轻微自旋，接触阴影缩小 |
| 滞空 | 0.10s | 顶点悬停，给“跃起”留辨识时间 |
| 砸落 | 0.16s | `TRANS_QUART/EASE_IN` 急速下坠，身体压扁 |
| 踩扁 | 0.10s | 目标方瞬间压成 `y=0.06` 的薄片，并生成一枚深色“滩” |
| 溅开 | 0.55s | 新增 `puddle(pos,color)`：扁平圆盘 0.25→1.7 倍、淡出；10 片碎屑四散；两圈冲击波 |
| 收势 | 0.30s | 攻击方恢复站姿并做胜利小跳 |

- `src/Main.gd` 吃棋处 `Engine.time_scale = 0.5`，结束后恢复 `BASE_TIME_SCALE`；总真实时长控制在 2.2–2.6s。
- 新增 `Arena.puddle()`（独立节点，不挂在被吃棋子上），保证棋子复位时“滩”仍在。
- 被吃棋子动画结束后由主流程复位到基地，并显式恢复 `scale/rotation/modulate`，避免残留压扁状态。

### 3.3 荆棘 / 陷阱 / 传送
- `_thorn_punish`：新增尖刺从地里钻出（6 根锥体 0.18s 升起）→ 棋盘震动 → 棋子被顶起再落下 → 逐格后退 2 格（每格一次跳跃，不再一次瞬移）。总时长 ≈ 1.2s。
- `_portal_jump`：改为“吸入—喷出”：起点棋子缩小旋转 0.22s → 起点紫色传送门爆发 → 目标点传送门爆发 → 棋子放大旋转落位 0.28s。总时长 ≈ 0.9s。
- 事件卡中的 `trap` / `portal` 复用上述特效函数；`freeze_burst` 持续时间 +40%。

### 验收
- 录制/逐步截图：吃棋能看到蓄力、跃起、滞空、砸落、压扁成滩、碎屑、收势；目标最终回基地且无残留缩放。
- 荆棘、传送各截图 3 帧，效果顺序正确；单个特效不超过 1.5s。

## 5. 设置开关：吃棋改为小游戏对决

### 决策
- 新增设置项「吃棋对决（石头剪刀布）」，默认**关**（保持直接吃）。
- 开启后：攻击方出拳，守方随机；`(攻 - 守 + 3) % 3 == 1` 判攻击方胜。
- 平局按失败处理；失败/平局 → 攻击方退回吃棋前的格子（落点前一格），守方留在原地；成功 → 走原有吃棋逻辑（护盾仍可免疫）。
- 限时 4 秒，倒计时结束自动随机出拳，保证一局几秒内结束。
- AI 攻击方随机出拳，不弹面板；自动演示/无头模式不等待。

### 改动
- `src/Hud.gd`：
  - 新增信号 `duel_chosen(pick: int)`、`duel_toggled(on: bool)`。
  - 设置页新增开关按钮，状态写入 prefs 键 `duel`。
  - 新增对决面板：显示「红队 → 蓝队 #3」、石头/剪刀/布三个大按钮、4 秒倒计时条；选中后展示双方出拳与胜负结果 0.8s，再 `duel_chosen.emit(pick)`；超时自动随机。
  - 面板 `mouse_filter` 只在显示时拦截，关闭后不挡棋盘。
- `src/Main.gd`：
  - 新增 `var duel_enabled := false`，随 prefs 读写（`"duel"`）。
  - `_advance()` 记录落点前一格 `from_cell`，传入 `_resolve_capture(p, from_cell)`。
  - `_resolve_capture(p, from_cell)`：
    - 未开启 → 原有逻辑。
    - 开启 → 取攻/守队伍；本地人类攻方 `await hud.duel_chosen`；AI/无头直接随机；LAN 客机攻方见 5.1。
    - 胜 → 继续原有吃棋；负/平 → `_hop_to(p, from_cell)` 退回并记录战报「对决失利，退回原位」。
  - 新增 `var _duel_pick := -1`、`_duel_active := false`、`_duel_until := 0`。

### 5.1 LAN 对决
- 房主权威：客机作为攻方时，房主在 `_resolve_capture` 内置 `_duel_active=true` 并立即推送状态；快照增加 `duel:{active,team,until}`。
- 客机 `_apply_net()` 看到 `duel.active && duel.team == net_guest_team` → 打开对决面板；选择后发 `{a:"duel", pick:n}`。
- 房主 `_on_lan_intent()` 收到 `duel` 且 `_duel_active` → 写入 `_duel_pick`；最多等 5s，超时随机，再继续结算并推送 `duel.active=false`。
- 房主自己作为攻方：本地结算，不需要客机参与。

### 验收
- 关闭时吃棋行为与现在完全一致。
- 开启后：胜→吃子发生；负/平→攻方回到落点前一格，守方不动；4 秒不操作自动出拳。
- 存档/读档后设置保持；LAN 双端各触发一次对决，状态签名最终一致。

## 6. 道具使用 3D 演出（角色逐帧动画，不是粒子贴纸）

### 原则
每件道具都按「施法动作 → 传递 → 受击反应 → 结果」四段演出，**由动画驱动状态**：棋子先动，状态在命中帧才写入，不能先改数据再放特效用“闪一下”代替。单件总时长 0.7–1.7s，期间不弹模态框；群体/连锁效果按 0.08–0.12s 间隔依次触发。HUD 顶部文字条只负责补齐「谁 → 对谁 → 道具 → 效果」，不承担主要表现。

### 新增动画原语（`src/Arena.gd`）
- `anim_windup(node, color)`：重心后坐、身体后仰、抬起武器/手臂，脚下浮起同色符文环，能量粒子沿身体螺旋上升汇入武器；0.25s。
- `anim_release(node, color)`：上身猛前压，武器/手掌前推，脚下炸出一圈冲击环，身体有 0.1s 拉伸；0.12s。
- `piece_recoil(node, dir, power)`：受击方身体先压扁 15%，再沿受力方向倾斜并滑出 20–30 单位，最后回正；0.3s。用身体位移做反馈，不用闪白代替。
- `piece_launch(node, to, height)`：整枚棋子翻滚着沿抛物线飞出，带缩小接触阴影与拖尾，落地弹跳一次并扬起灰尘；0.6–0.8s。
- `piece_dissolve(node)` / `piece_reassemble(node)`：身体拆成 24 块碎片，碎片螺旋收缩进地面/光点，再在目标点由碎片合拢成完整棋子；各 0.35s。
- `orb_fly(from, to, color, trail, dur)`：发光弹体沿浅弧线飞行，尾迹按 `trail` 变化（冰晶/火焰/金色卡牌/黑雾），命中帧触发 `impact`。
- `impact(kind, pos, color)`：`ice` = 冰晶外壳从脚到头包裹目标，伴随冰雾与冰锥环；`fire` = 火柱与余烬、地面焦痕；`hit` = 冲击闪光 + 碎屑；`drag` = 锁链/光束绷紧。
- `tether(from, to, color)`：从施法者手心射出的能量索，命中后绷直，被拖动的棋子身体前倾、脚底摩擦出尘。
- `aura_bind(node, color, shape)`：光环从脚底升起、收束到身体，留下持续可见的护盾/加速边缘光，直到效果结束。
- `card_arc(from, to)`：一张卡牌实体旋转着沿弧线飞回施法者手中。
- `decal_scorch(pos)`：焦痕贴片，6s 内淡出。
- `item_glyph(node, item_id)`：施法者头顶升起该道具的 3D 图标，放大展示 0.25s 后飞向目标（解决“不知道用了什么”）。

- `src/Hud.gd`：顶部信息条 `show_item_cast()` 保留为轻量补充：左侧队伍色块、`红队`、`使用了 狙击`、`→ 蓝队 3 号`、下行 `击退 3 格`；0.2s 滑入、1.4s 停留、0.3s 淡出，不拦输入、不遮挡棋盘中心。保留 `show_item_toast` 仅用于“获得道具”。
- 同步性：`frozen` 在冰壳闭合帧写入；`swap` 在落地帧交换 `cell`；`bomb` 在目标落入基地帧改写；保证动画、数据、联机快照一致。

## 7. 「换位」道具 bug 修复

### 7.1 实测现象
- 施放后观感像“把对方牵引过来”，两枚棋子没有互相对调。
- 目标站在其胜利通道那一格时，换位直接不触发（点了没反应，或报“没有可以换位的对手棋子”）。
- 棋盘其他位置也不像真正交换，先动一枚、再动另一枚，像单方面拖拽。

### 7.2 根因（代码位置均已核对）
1. **只交换了环道 cell，没有“通道占位”概念。** `src/Main.gd` 的 `swap` 分支（约 2302–2321 行）只有 `mine["cell"] = op_cell; p["cell"] = my_cell` 两句，`finished / lane / lslot` 一律不动。棋子一旦进入终点跑道，坐标语义就脱离了 `cell`，只交换 `cell` 等于把“最后一个环道格”当成它的位置，通道格被忽略。
2. **候选池把终点跑道上的棋子整个排除。** 选目标时（约 2216 行）条件是 `q["team"] == current_team or q["finished"] or q["cell"] < 0: continue`，已完成（`finished == true`）的棋子进不了池子。所以“对方站在自己的通道那一格”时根本选不中，表现为“完全没成功”。
3. **通道格与环道格是两套索引体系。** 路径 `paths[team]` 只覆盖环道；通道是 `GL[team]_[slot]` 四个点。旧实现把 `cell` 当作唯一位置源，通道位置没有任何字段能表达，任何“是否可落点”的判断都只看环道，通道格天然被判成非法。
4. **动画顺序是“先我后他”，观感就是牵引。** `await _hop_to(mine, …)` 走完才 `await _hop_to(p, …)`，视觉上第二枚是被第一枚“拉”过去的，不是两人同时换位。

### 7.3 决策：用 `lane / lslot` 表达通道占位，交换“完整占位”
- 棋子字典新增 `lane`（`-1` = 在环道；`0..3` = 站在某队通道）与 `lslot`（通道槽位 `1..4`）。
- `finished` 不再是独立状态，改为推导值：`finished = (lane == team)`。到终点就是“站在自己的通道格里”。
- 换位交换的是三元组 `(cell, lane, lslot)`，落地帧一次性写入，`finished` 随之重算。
- 通道格是队伍私有的：**异队棋子不得占据**。因此交换前先试算目标占位，若某方会被换进别人的通道，则退化为「拽出」：通道里那枚被拽到对方原格（清空 `lane`、取消完成），通道外的棋子原地不动。这条规则保证任何交换都不会把棋子永久锁死在对方终点区、导致无法取胜。

### 7.4 四种场景的确定性结果
| 场景 | 结果 |
|---|---|
| 普通格 ↔ 普通格 | 双方完整互换，同时起跳、同时落地。 |
| 对方在**其自己的**通道（已完成） | 对方被拽出通道，落到我方棋子原格并恢复可行动；我方棋子不动（异队不可进通道）。战报写「拽出对方通道」。 |
| 对方在**我方**通道（历史/联机异常占位） | 我方棋子进入自己的通道格（判定完成），对方落到我方原格。这是真正的互换。 |
| 通道 ↔ 普通格交叉（我方棋子已在对方通道） | 对方回自己的通道格，我方棋子回到对方的环道格，互换成立。 |
| 双方都在通道 | 按“异队不可进通道”判定：能进的一方进，不能进的一方执行拽出，另一方回到环道。 |

### 7.5 改动点
- `src/Main.gd`
  - `_spawn_pieces()`：棋子字典加 `"lane": -1, "lslot": 0`。
  - `_piece_cell_pos()`：`lane >= 0` 时返回 `_goal_pos(lane, lslot)`，优先级高于 `cell`。
  - `_legal_moves()`：`lane >= 0` 的棋子不参与掷骰移动（它已经到终点区）。
  - `_finish_piece()`：用 `_free_goal_slot(team)` 取空槽，写入 `lane = team`、`lslot = slot`、`cell = FIELDS-1`；新增 `_free_goal_slot(team)`。
  - `_check_win()`：条件改为“所有棋子 `lane == team`”。
  - 换位候选池：去掉对 `finished` 的排除，改为只排除基地（`cell < 0` 且 `lane < 0`），通道内棋子可被选中。
  - `swap` 分支：按 7.3 算法交换三元组；先算好双方落点，再调用 `await arena.piece_swap_arc(a_node, b_node, color)` 同时起飞，落地帧才写 `cell/lane/lslot`，随后重算 `finished`、`_check_win()`、`_update_all()`。
  - 存档：`_capture_state()` 棋子行加 `l`（lane）、`ls`（lslot）；`_apply_sections()` 读回并按 `finished` 推断旧档（旧档 `finished && lane < 0` → `lane = team` 并分配空槽）。
- `src/Arena.gd`：新增 `piece_swap_arc(a, b, color)`——两枚棋子同时被金色能量索提起，沿左右对称弧线交叉飞过（一高一低错开避免穿模），中途各留 3 个残影，落地时两圈光环炸开；总时长 1.2s。替换原来两次串行 `_hop_to` 的表现。
- `src/Hud.gd`：换位选目标时，通道内棋子的标题追加「已到达终点区」，让玩家知道它为什么可以被换。

### 7.6 验证方式
1. **单元级**：`--selftest-swap`（新增）构造四个场景，打印交换前后的 `(team, cell, lane, lslot, finished)`，断言四种场景都符合 7.4 表。
2. **观感级**：`--auto` 跑到第一次换位，逐帧截图 4 张（蓄力、双起飞、交叉、落地），确认两枚同时移动、方向相反。
3. **通道场景**：手动把红队一枚棋子推到通道（或用 `--selftest-swap` 预置），对蓝队环道棋子用换位，确认蓝队被拽出、红队原地不动、战报文案正确。
4. **回归**：换位后立刻掷骰、再换一次、吃棋、存档读档，确认 `lane/lslot` 不丢、`_check_win` 判定正确。

## 9. 风险与约束

- 相机放大以截图实测为准，必要时在 3040 基线上下微调，但必须保证“整盘在屏内”优先于“更大”。
- 吃棋动画必须成对恢复双方 `scale/rotation/position`，避免二次吃棋出现残留。
- LAN 对决为异步等待，必须有超时兜底，不能阻塞回合。
- 所有新增文案使用中文；不改存档格式版本，避免旧档失效。
- `finished` 改为由 `lane` 推导后，旧存档通过 `_apply_sections()` 的迁移分支补齐，不允许出现 `finished == true` 但 `lane < 0` 的脏状态。
- 换位必须先算后演、落地帧才写数据；动画中断（重开/退出）不得留下半交换状态。
